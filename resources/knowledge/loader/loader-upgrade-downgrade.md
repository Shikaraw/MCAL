## 症状

- 把 1.20.1 整合包直接升到 1.21 后启动失败，日志刷 `Missing or unsupported mandatory dependencies`；
- 用旧版本打开升级过的新世界时报 `Chunk file at ... is in the wrong location` 或世界直接损坏；
- 升级加载器补丁版（如 Forge 47.1 → 47.2）后个别存档的机器/方块实体异常；
- 降级游戏版本后世界打不开或崩溃。

## 原因

- **世界数据格式只升不降**：新版本会在加载时把区块升级到新格式（也写入新方块/实体 id）。降级打开时这些内容无法识别，表现为区块错误、方块消失甚至世界损坏。启用了「实验性功能/实验性数据包」的世界降级必坏。
- **模组与加载器绑定**：每个模组构建只针对特定 MC 版本 + 加载器；跨版本不会自动适配。加载器补丁升级（同 MC 版本内）通常安全，大版本升级/降级则需要整套模组重换。
- **Java 要求同步变化**：1.20.5+ 必须 Java 21（见 [[java-version-matrix]]），升级游戏却不换 Java 会在加载前就报 Unsupported class file major version。
- **配置与存档数据**：`config/` 通常能沿用，但模组自身的存档数据（机器 NBT、维度数据）跨版本可能读不出来，作者未提供迁移时只能重新生成或放弃。

## 解决方案

1. **升级前完整备份**：复制 `saves/`、`config/`、`mods/` 到实例目录外；服务器先 `/save-off` 再整目录备份 world。
2. **新建实例做迁移，不要原地改版本**：在启动器里复制旧实例为新实例，改新实例的游戏版本与加载器，旧实例保持可玩。
3. 逐个替换模组：以模组发布页/整合包更新日志为准，找出新版本对应构建；没有对应构建的模组只能取舍（找替代品或放弃）。
4. 同步调整 Java：1.16.5 → Java 8，1.17–1.20.4 → Java 17，1.20.5+ → Java 21。
5. 先开一个**新世界**验证整套组合能正常运行，再尝试复制旧世界测试；确认旧世界能打开且物品/机器正常后，才把旧世界作为主世界使用。
6. **不要用降级来「复活」升级后出问题的世界**：降级不会还原已被新版本改写的区块。降级仅适用于还没被新版打开过的存档。
7. 加载器补丁降级（如 Forge 47.2 → 47.1）：一般可以，但升级过的 Forge 配置/模组数据也可能不兼容，降级前同样备份；模组版本要一起降。

## 验证

新版实例能启动、加载备份世界的副本后出生点正常、跑图若干区块无区块错误；`logs/latest.log` 无依赖缺失与区块格式报错；打开的原世界副本里关键机器/存储内容仍在。
