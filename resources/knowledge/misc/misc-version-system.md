## 症状

- 启动器版本列表里全是 `24w45a`、`1.21.4-pre2`、`1.21.4-rc1`，不知道选哪个；
- 下载模组时页面写 `1.21.4` 但自己装的是 `1.21.4-pre1`，启动报版本不匹配；
- 新版本加了想玩的内容，但模组还不支持；
- 旧存档被新版本「升级」后再也回不去。

## 原因

Java 版的版本分几类：

- **正式版（release）**：形如 `1.21.4`，主版本号 `21` + 补丁号 `4`；1.21.2 之后的版本号第三段开始承担小版本迭代。正式版是模组、服务器与存档的稳定基准。
- **快照（snapshot）**：开发中的每周构建，命名 `YYwWWx`，如 `24w45a` = 2024 年第 45 周的第 1 个快照；`25w03a` 同理。快照随时可能改协议与数据格式，存档升级后可能无法回退。
- **预发布（pre-release）**：`1.21.4-pre1`、`pre2`，功能已冻结，只修 bug，仍可能改协议。
- **候选版（release candidate）**：`1.21.4-rc1`，理论上就是最终版，只等确认。
- 更早有 Alpha/Beta（`a1.2.6`、`b1.7.3`）与旧正式版（`1.8.9`、`1.12.2` 等）。

模组与光影只针对具体版本构建（如 `1.21.4` 与 `1.21.4-pre1` 可能不兼容），快照通常没有模组支持。数据包/资源包的 `pack_format` 也随版本变动。

## 解决方案

1. **选择建议**：长期游玩与开模组服选正式版中的「锚点版本」——模组生态最全的如 1.8.9、1.12.2、1.16.5、1.17.1/1.18.2、1.20.1、1.21.1；新内容尝鲜用快照但接受不稳定。
2. 装模组前核对版本号精确到补丁：`1.20.1` 的模组不要装进 `1.20.2`，`1.21.1` 与 `1.21.4` 之间也常不通用（NeoForge 尤其严格）。
3. 快照游玩前：单独建实例、单独存档，不要用主存档打开快照；官方启动器会提示快照存档的风险，接受后不可回退。
4. 服务器：正式版发布后服务器升级要等模组/插件适配；快照服仅供测试，玩家需同样使用快照客户端。
5. 版本号解读：`1.21.4` 中 `21` 为特性版本、`4` 为小版本；`1.20.5/1.20.6`、`1.21.2/1.21.3` 这类相邻小版本往往伴随数据格式变化，升级前备份（见 [[loader-upgrade-downgrade]]）。
6. 实验性内容：新功能可能以「实验性数据包/实验性开关」形式提供，启用了的世界**不能安全降级**；想回退只能使用升级前的备份。

## 验证

启动器显示的版本号与计划一致（正式版/快照一目了然）；模组与光影版本页面标注与实例版本完全匹配；存档在版本切换后可正常加载（或恢复自备份）。
