## 症状

- 换上 128x/256x/512x 高清材质后帧数骤降、进游戏加载贴图时卡住十几秒；
- 长时间游玩后画面发白、贴图错乱，Windows 提示「显示驱动已停止响应并已恢复」；
- 游戏崩溃且崩溃报告与 `OutOfMemoryError` 无关，日志停在 `Rendering overlay`/贴图加载附近；
- 4K 分辨率下材质包加载后直接黑屏。

## 原因

- 材质分辨率每提高一档（32x → 64x → 128x），单个贴图像素数按平方增长，显存占用也近似平方增长；贴图图集（atlas）在启动时上传到 GPU，显存不足会触发驱动重置或渲染错误。
- 游戏同时保留 CPU 侧的像素缓冲用于上传与 mipmap 生成，这部分占堆内存，但量级远小于显存；堆内存不够通常先表现为 `OutOfMemoryError: Java heap space`（见 [[crash-out-of-memory]]）。
- mipmap 等级、各向异性过滤、光影与超分辨率设置都会额外放大显存占用。
- 集显与共享显存机型（核显显存从系统内存划出）最容易被高清材质击穿。

## 解决方案

1. 按显存预算选择：
   - 2 GB 显存：64x 以内，且关闭光影；
   - 4–6 GB：64x 常态，128x 需关光影或降分辨率；
   - 8 GB 以上：128x 较稳，256x 仍建议只在 1080p 探索性使用。
   集显/共享显存机型按 64x 以内安排。
2. 游戏内设置：Video Settings → Quality → Mipmap Levels 用 4（更高收益小、开销大）；关闭 Anisotropic Filtering（或 ≤4）；渲染距离降到 8–12；分辨率保持显示器原生，不要开 DSR/虚拟超分辨率叠加。
3. 确认加载失败不是内存问题：崩溃报告里若是 Java 堆溢出，按 [[crash-out-of-memory]] 调 `-Xmx`；若日志无 Java 异常但驱动重置，则是显存/驱动问题，降低材质分辨率即可。
4. 使用支持按需加载的优化模组（Sodium/Embeddium 本身对贴图上传有优化），单线程老渲染链下 256x 更容易出问题。
5. 服务器/整合包自带的高清材质若不可协商，可将「自定义天空、GUI、字体」等非必要高清文件裁掉，只保留方块/物品核心内容，显著减轻负担。
6. 驱动侧：用厂商推荐版本；笔记本确认游戏跑在独显（见 [[graphics-gpu-selection]]）。

## 验证

加载材质包后帧率回到可接受范围（相对原版材质下降不超过约一半），连续游玩 20 分钟无白屏、无驱动重置事件；重启游戏后加载不再长时间卡在贴图生成阶段。
