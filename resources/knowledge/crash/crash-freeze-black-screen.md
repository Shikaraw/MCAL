## 症状

- 启动器显示游戏进程已启动，但没有窗口，或窗口全黑/白屏且鼠标转圈；
- 加载进度条停在同一位置不动（如「Loading Minecraft」「正在构建地形」）；
- 任务管理器中 javaw.exe 占着 CPU 或内存不动，没有 `crash-reports/` 生成；
- 有时等几分钟后自己恢复，有时永远不动。

## 原因

这类问题没有崩溃报告，因为进程根本没走到「捕获异常 → 生成报告」的流程。常见原因：

- **模组在初始化/网络请求里阻塞**：某模组启动时联网校验、读大文件、死循环；整合包里两个模组互相等锁。
- **资源加载过重**：首次启动要解压、扫描几百个模组和材质，磁盘慢或机械硬盘时会长时间卡住。
- **显卡驱动/GL 上下文创建失败**：窗口创建失败但没报错退出（老驱动 + 1.17+、远程桌面、虚拟机）。
- **内存不足前的挣扎**：GC 占满 CPU，界面冻结，随后可能 OOM，参考 [[crash-out-of-memory]]。
- **窗口跑到屏幕外**：多显示器配置变化后窗口坐标落在不可见区域，看起来像黑屏。
- **杀毒软件/安全软件**在扫描 jar 与读写时的拦截。

## 解决方案

1. **先看日志尾部**：打开 `.minecraft/logs/latest.log`，拉到最底，最后一行通常就是卡住的位置（某个模组名、`Preparing spawn area`、`Downloading assets`）。用 [[crash-read-crash-report]] 的思路读它。
2. **看资源占用**：任务管理器里看 javaw.exe。CPU 100% 且内存不高 → 死循环或 GC；内存接近上限 → 见内存文章；CPU 接近 0 且磁盘持续读写 → 正在解压/扫描，多等一会。
3. **首次启动耐心等待**：大型整合包首次启动 5–15 分钟属正常（要处理上千个文件），第二次启动会明显变快。
4. **把窗口找回来**：按 `Alt + Space` 打开窗口菜单 → 移动 → 方向键把窗口拖回屏幕；或在 `options.txt` 中删掉窗口位置相关行（关闭游戏后操作）。
5. **模组二分**：把 `mods` 目录整体备份后清空，只留前置模组能启动 → 再放一半进去，逐步定位卡住的模组。
6. **更新/回退显卡驱动**，确认没有用远程桌面/虚拟机的软件渲染；笔记本为 `javaw.exe` 指定独显。
7. **临时关闭杀毒实时防护**（Windows 安全中心 → 病毒和威胁防护 → 管理设置）测试，若恢复则把游戏目录与 Java 目录加入白名单。
8. 确认游戏版本对应的 Java 正确（[[java-version-matrix]]），并给整合包足量内存（8 GB 以下堆容易在加载期就卡）。

## 验证

用定位后的最小配置启动，10 分钟内进入标题界面；重复启动 3 次均能看到主菜单；`latest.log` 末尾出现 `Stopping!`/正常启动完成日志，且任务管理器 CPU 回落到低位。
